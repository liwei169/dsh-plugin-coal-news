# 煤矿资讯插件 · 需求清单与实现方案

- 版本：v0.1（2026-11-25）
- 包名：`dsh-plugin-coal-news`
- 状态：设计稿，待确认第 12 节的三项决策后进入实现

---

## 1. 一句话定位

在 DSH 里常驻一块「煤矿行业信息板」：按科技 / 安全 / 价格 / 政策分类浏览最新动态，30 秒自动刷新，点标题看原文；可选把同一份数据做成 Agent 工具，让模型回答「最近煤矿有什么事故 / 焦煤什么价」。

---

## 2. 三条关键结论（先看这个）

| # | 结论 | 依据 |
| --- | --- | --- |
| 1 | **抓取必须放在 Host 侧，不能在浏览器里直连资讯站** | 中文资讯站基本不发 CORS 头，浏览器直连会被跨域拦截；Host 侧用全局 `fetch`，由宿主统一套用用户代理设置，也不受防盗链 Referer 拦截 |
| 2 | **「30 秒刷新」要拆成两层**：界面 30 秒取一次本地快照，上游按源分级刷新（资讯 5–15 分钟、行情 30–60 秒），带 ETag / 退避 | 30 秒直接打 10 个站点，几分钟内就会被限流或封 IP；而行情接口本身就适合高频 |
| 3 | **价格和资讯分开做**：价格走行情接口（JSON、可 30 秒），资讯走列表页解析（政府站是服务端渲染，已验证可解析） | 已实测：国家矿山安全监察局首页返回 200 且是静态 HTML 列表；行情 JSON 接口可达但 `secid` 需逐个核对 |

**技术通路（已核对当前安装的源码）**：Host 侧 `ctx.connection.rpc.handle(channel, handler)` 注册逻辑通道，浏览器侧 `ctx.connection.rpc.call(channel, endpoint, payload, signal)` 调用，返回 `{ ok: true, value }` 或 `{ ok: false, error }`。桌面版走 IPC、网页版走 `/api`，同一份插件代码两种形态都能用 —— 所以不能用裸 `ctx.webServer` 路由（桌面版页面是 `file://`，拿不到同源）。

## 3. 功能需求清单

优先级：P0 = 首个可用版本必须有；P1 = 第二个版本；P2 = 可选/后续。

| --- | --- | --- | --- |

| FR-02 | 每 30 秒自动刷新，可手动刷新、可暂停 | P0 | 连续运行 30 分钟无内存增长；暂停后不再发请求；手动刷新 1 秒内给出反馈 |

| FR-13 | 首次打开秒开：用上次快照先渲染，再后台刷新 | P0 | 打开面板 200ms 内出现列表（哪怕数据是旧的），并显示「更新于 xx」 |

## 4. 数据源清单与获取方式

原则：**一个源一个适配器**，单源失败不影响整体；只取「标题 + 链接 + 时间（+ 来源栏目）」，不转载全文。

| 类别 | 来源 | 获取方式 | 建议频率 | 风险 / 备注 |
| --- | --- | --- | --- | --- |
| 安全 · 政策 | 国家矿山安全监察局 `chinamine-safety.gov.cn`：要闻、地方信息、通知公告、事故查处、事故案例 | HTML 列表页解析（已验证：服务端渲染、`<a>` 带 `title`、URL 内含日期如 `/202611/t20261123_740427.shtml`） | 10 分钟 | 栏目改版需更新选择器；事故案例栏目更新慢，属正常 |
| 政策 | 国家能源局 `nea.gov.cn`、国家发改委 `ndrc.gov.cn`、应急管理部 `mem.gov.cn` | HTML 列表页解析 | 15–30 分钟 | 栏目分散，首版只取煤炭/能源相关栏目 |
| 行业资讯 | 中国煤炭报 / 中国煤炭网 `ccoalnews.com`、中国煤炭工业协会 `coalchina.org.cn` | HTML 列表页解析（coalchina 实测返回 202，疑似有 WAF，需带浏览器 UA + Referer） | 10 分钟 | 反爬较强，作为「尽力而为」源 |
| 价格 · 指数 | 中国煤炭市场网 `cctd.com.cn`（CCTD 秦皇岛动力煤价格） | HTML 解析（实测首页正文转换失败，需具体栏目/接口） | 日更（每日一次即可） | 站点较重，待验证；失败时价格看板只显示期货并标注「指数暂不可用」 |
| 价格 · 期货 | 行情 JSON 接口（东方财富 `push2.eastmoney.com` 已验证可达；新浪 `hq.sinajs.cn` 需 Referer + GBK 解码） | JSON，30–60 秒 | 快 | `secid` / 合约代码要一个个核对；只取主连，不做行情推送 |
| 降级 | 任意 RSS / Atom、或用户自填的列表页 | 通用 RSS 适配器 | 按源 | 首版不做，预留 `type: 'rss'` 适配器位置 |

> 合规：只抓公开页面、限频、带 UA、遵守 robots.txt；展示时保留来源与原文链接，不缓存全文、不做二次分发。

## 5. 总体架构与数据流

```
┌─────────────────────────── Host 进程（Node） ───────────────────────────┐
│  index.js                                                              │
│  ┌──────────────┐   ┌──────────────┐   ┌───────────────┐               │
│  │ 源适配器 ×N   │→ │ 归一化 / 去重 │→ │ 内存缓存 + TTL │               │
│  │ (fetch+解析)  │   │ (NewsItem)   │   │ + ETag + 退避  │               │
│  └──────────────┘   └──────────────┘   └───────┬───────┘               │
│         ↑ 定时器（按源频率，jitter）              │                       │
│                                                 ↓                       │
│                          ctx.connection.rpc.handle('/coal-news', …)     │
│                          （另可选：ctx.tools 注册 coal_news 工具）         │
└─────────────────────────────────┬───────────────────────────────────────┘
                                  │ IPC（桌面）/ /api（网页）
┌─────────────────────────────────┴───────────────────────────────────────┐
│  client.js（浏览器）                                                     │
│  面板组件 → 30s 轮询 rpc.call('/coal-news','feed') → 渲染分类/价格/状态     │
│  本地快照（localStorage）用于秒开；可见性变化时暂停/恢复轮询                 │
└─────────────────────────────────────────────────────────────────────────┘
```

职责划分：

| 位置 | 负责 | 不负责 |
| --- | --- | --- |
| Host `index.js` | 抓取、解析、归一化、去重、缓存、退避、暴露 RPC、可选工具 | UI、渲染、用户交互 |
| Client `client.js` | 面板、分类、筛选、轮询、本地快照、状态展示 | 任何跨域请求、任何解析 |

### 5.1 RPC 契约

通道 `/coal-news`，全部为只读查询（`refresh` 只触发后台刷新，不阻塞）：

| endpoint | 入参 | 返回 |
| --- | --- | --- |
| `feed` | `{ categories?: ('tech'\|'safety'\|'price'\|'policy')[], since?: ISO8601, limit?: number }` | `{ items: NewsItem[], fetchedAt, stale, errors: SourceError[] }` |
| `quotes` | `{}` | `{ quotes: Quote[], fetchedAt, stale }` |
| `status` | `{}` | `{ sources: [{ id, name, category, lastOkAt, lastErrorAt, error, stale }], cacheAgeMs }` |
| `refresh` | `{ sources?: string[] }` | `{ accepted: true }` |

```ts
interface NewsItem {
  id: string            // sha1(规范化 URL)，用于去重
  title: string
  url: string
  source: string        // 来源站点中文名
  category: 'tech' | 'safety' | 'price' | 'policy'
  publishedAt?: string  // ISO8601；解析不出时间时缺省
  fetchedAt: string
}

interface Quote {
  symbol: string        // 如 'JM0'（焦煤主连）
  name: string
  price: number
  change: number
  changePct: number
  unit?: string
  updatedAt: string
}
```

约定：Host 永远返回 `ok`，把「某源失败了」表达成 `stale: true` + `errors[]`，而不是整体报错 —— 界面才不会因为一个源挂掉变成空白。

### 5.2 缓存与去重规则

- 每个源一个 `lastOkAt / lastErrorAt / etag / lastModified / backoffUntil`；
- 抓取时带 `If-None-Match` / `If-Modified-Since`，304 视为成功且零成本；
- 规范化 URL（去 `utm_*`、去锚点、统一协议/尾斜杠）后取 `sha1` 作为 `id`；
- 每个分类最多保留 300 条，按 `publishedAt`（缺失则 `fetchedAt`）倒序；
- 单源连续失败 5 次进入熔断：只保留旧数据并标注，30 分钟后半开重试。

## 6. 「30 秒刷新」的正确做法

用户要的是「30 秒就能看到变化」，不是「30 秒抓一次站点」。三层执行：

| 层 | 周期 | 说明 |
| --- | --- | --- |
| 界面轮询 | 30 s | `rpc.call('feed')` 只读内存快照，代价约 1 次本地 IPC，可忽略 |
| 上游刷新（资讯） | 5–15 min / 源 | 带 ETag、UA、jitter（±20%），并发上限 3，单请求超时 8 s |
| 上游刷新（行情） | 30–60 s | 单个 JSON 接口，一次请求拿全部合约 |

配套规则：

1. **暂停条件**：面板折叠、页面 `document.visibilityState === 'hidden'`、连续 3 次失败后用户选择「稍后重试」→ 停表；
2. **恢复**：可见性恢复或展开面板时立即补一次，再重新计时（不等 30 s）；
3. **退避**：源失败按 30 s → 1 min → 2 min → 5 min → 15 min 递增，成功即复位；
4. **不叠加**：上一次请求未结束不发下一次，用 `AbortController` 在组件卸载/切分类时取消；
5. **可感知**：界面显示「更新于 10:32:15（30 秒前）」，让用户知道刷新真的在跑。

## 7. 界面与交互

**推荐形态（P0）**：沿用当前骨架的 `shell.overlay` 左下浮层，可折叠；宽 320–360px，最高 480px，列表虚拟化不做（300 条撑得住），超出滚动。

后续可选（P1）：右侧边栏 tab（`ctx.sidebarRightTabs.register` + `sidebar.right.pane.tab`），信息量大时更合适 —— 首版不做，避免一次引入两个新机制。

结构与状态：

```
┌──────────────────────────────────┐
│ 煤矿资讯   [全部][科技][安全][价格][政策]  ⟳  － │
├──────────────────────────────────┤
│ 焦煤主连 1,234.5  +1.2%  ↑       │  ← 价格条（FR-04）
├──────────────────────────────────┤
│ ● 山西某矿瓦斯超限被责令停产        │
│   国家矿山安全监察局 · 12 分钟前    │  ← 行：标题 / 来源 · 相对时间
│ ● ...                            │
├──────────────────────────────────┤
│ 更新于 10:32:15 · 部分来源不可用 ⚠  │  ← 页脚状态
└──────────────────────────────────┘
```

| 状态 | 表现 | 动作 |
| --- | --- | --- |
| 首次加载 | 3 行骨架屏 | — |
| 有旧快照 | 直接渲染旧数据 + 「更新中」 | — |
| 空 | 「该分类暂无更新」 | 切回「全部」 |
| 错误（全部源挂） | 「暂时取不到数据」+ 原因 | 重试 / 打开源站 |
| 部分源失败 | 正常列表 + 页脚 ⚠「N 个来源不可用」 | 点开看是哪些 |
| 过期 | 页脚「数据更新于 2 小时前」 | 手动刷新 |

细节：

- **主题**：只用 `--dsw-alias-*` token（`--dsw-alias-bg-layer-3`、`--dsw-alias-label-primary/secondary`、分隔线 token），不写死颜色，暗色自动跟随；
- **排版**：标题 13px/20px，来源 12px，最多两行截断（`-webkit-line-clamp`）；
- **i18n**：所有文案走 `locale/zh.json` + `locale/en.json`，组件内不写死中文；
- **无障碍**：分类 chip 用 `role="tab"` + `aria-selected`，折叠按钮 `aria-expanded`，`Esc` 收起面板，键盘可达，焦点样式不覆盖；
- **不做**：不改根节点、不往 `document.body` 追加、不读别的插件的 DOM/CSS。

## 8. 配置项

| 层 | 内容 | 实现 |
| --- | --- | --- |
| 内置源表 | 源 id、名称、URL、分类、刷新间隔、选择器 | `index.js` 内的常量数组（首版） |
| 用户偏好 | 刷新间隔（30/60/300 s）、默认分类、涨跌配色、启用的源、收藏 | 浏览器 `localStorage`，随 `feed`/`status` 请求带给 Host |
| 部署级配置 | 若确认宿主 `Config`（schemastery schema）对独立 npm 包可用，再把源表与间隔暴露到 `cordis.patch.yml` | P2，待验证 |

> 为什么不一开始就用 `Config`：独立发布的 npm 插件不保证能 `import '@deepseek-ai/schemastery'`（宿主内部包不一定可从插件目录解析）。首版坚持**零宿主依赖**（只用 Node 内置 + 全局 `fetch`），可发布性优先。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 站点改版 / 反爬（403、WAF、202 挑战） | 单源失效 | 适配器隔离 + 源健康状态 + 熔断；政府站优先，商业站只作补充 |
| 中文编码（GBK/GB2312） | 乱码 | 显式按响应头/`<meta charset>` 解码，`TextDecoder('gbk')` |
| 时间解析 | 排序错乱 | 优先从 URL 提取 `YYYYMM`/`YYYYMMDD`，其次匹配正文日期，最后用 `fetchedAt` |
| 30 秒高频被限流 | 封禁 | 见第 6 节分层 TTL + 退避 + 可见性暂停 |
| DSH 版本差异（slot 名、connection API 变化） | 装不上/白屏 | 首版只用已核对接口；`engines`/README 标注验证过的 DSH 版本；slot 注册包 `try/catch` 并在失败时留日志 |
| 独立包的导入限制 | 依赖解析失败 | 零宿主依赖；不 `import` `@deepseek-ai/*` |
| 内容合规 | 版权/转载风险 | 只存标题与链接，正文跳原文，署名来源 |
